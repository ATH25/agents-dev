## Project status

This is a CrewAI crew project (`[tool.crewai] type = "crew"`, `crewai[tools]==1.14.1`, Python `>=3.10,<3.14`). It is being turned from the generated `crewai create` scaffold into a **single-agent Coder Crew**. The agent writes a Python file in a sandbox, runs it, and saves the code plus a summary to `output/code-task-output.md`.

The code in `src/coder/` is **still the unmodified scaffold**: `researcher` and `reporting_analyst` agents, `{topic}` and `current_year` inputs, and `report.md` output. The README also still describes that scaffold. The target design is spread across three docs, and they are the source of truth:

- `requirement.md`: FR-01 to FR-08, acceptance criteria AC-01 to AC-09, and open questions Q-01 to Q-09.
- `plan.md`: target architecture, sandbox options O-1/O-2/O-3 (§4.4), and phases P-01 to P-06.
- `tasks.md`: the task checklist (T-xxx). Only T-001 is done. Task IDs are stable: don't renumber them, and add new tasks at the end of a phase with the next free ID. Mark a task `[x]` only once it is implemented and verified.

`requirement-draft.md` is the original business draft. `prompts/prompt-1.md` is the prompt that generated the docs above.

Several decisions are **blocked on owner approval**: the sandbox mechanism, sandbox directory and limits (Q-01/Q-02/Q-04/Q-06), the assignment input interface (Q-03), and which entry points to keep (Q-09). Don't pick these yourself. Ask, or record the question in `tasks.md`.

## Commands

```bash
uv sync                                   # install deps
crewai run                                # run the crew (calls coder.main:run)
crewai test -n 2 -m <eval_llm>            # coder.main:test (argv: n_iterations, eval_llm)
crewai train -n <n> -f <file>.json        # coder.main:train
crewai replay -t <task_id>                # coder.main:replay
crewai reset-memories -a                  # clear memory (relevant once memory=True)
uv run python -c "import crewai; print(crewai.__version__)"
ruff check . && ruff format .
```

`tests/` is empty, so there is no test suite yet. Once one exists, run a single test with `uv run pytest tests/<file>.py::<test_name>`.

Environment note: the project has its own `.venv` and `uv.lock` (created by `uv sync` in T-002), with `crewai` and `crewai-tools` 1.14.1. The project `.env` holds only `MODEL`. `OPENAI_API_KEY` is set in the repo root `.env`, so plain `uv run` needs `--env-file ../../.env` until the key is added locally. The parent repo has a `.env.example` template.

## Architecture

CrewAI's classic YAML + decorator pattern:

- `src/coder/config/agents.yaml` and `tasks.yaml` define the agents and tasks. `{placeholders}` are filled in from `kickoff(inputs=...)`.
- `src/coder/crew.py` defines `@CrewBase class Coder`. Each `@agent` / `@task` method name **must match its YAML key exactly** (it loads `self.agents_config["<key>"]`, which keeps `# type: ignore[index]`). The `@crew` method builds a `Crew` from the auto-collected `self.agents` and `self.tasks`.
- `src/coder/main.py` holds the entry points registered in `pyproject.toml [project.scripts]` (`run`, `train`, `replay`, `test`, `run_with_trigger`). Every path that calls kickoff must pass the same input keys that the YAML templates reference.
- `src/coder/tools/` is where a custom `BaseTool` goes (currently a placeholder `custom_tool.py`).

Target wiring (`plan.md` §4):
- One `coder` agent with `llm: openai/gpt-5.4-mini`, set in YAML only.
- One `coding_task` that uses `{assignment}` and has `output_file: output/code-task-output.md`, set in YAML. Don't set `output_file` in `crew.py`.
- `main.py` rejects an empty `assignment` before kickoff and drops `topic`/`current_year`.
- `Crew(..., process=Process.sequential, verbose=True, memory=True, tracing=True)`.
- Sandbox rules: keep files inside the approved directory and reject path traversal. Run Python without shell command strings and with a timeout. Return stdout, stderr and the exit code to the agent. Never use `code_execution_mode="unsafe"` without explicit approval. `allow_code_execution` is deprecated in current CrewAI docs.

Leave `knowledge/user_preference.txt` unchanged. It's a scaffold sample and no requirement uses it.

## CrewAI-specific rules (from `AGENTS.md`)

`AGENTS.md` is a large CrewAI reference generated by `crewai create`. Read the relevant section before writing CrewAI code. The key points:
- CrewAI changes quickly. Before coding, check the installed version, PyPI (`https://pypi.org/pypi/crewai/json`) and the changelog (`https://docs.crewai.com/en/changelog`), and read the specific `https://docs.crewai.com/en/concepts/<feature>` page. If the docs and `AGENTS.md` disagree, the live docs win. An upgrade from 1.14.1 is not approved (T-003).
- Follow the patterns in `AGENTS.md`, not ones remembered from older CrewAI versions. Don't leave commented-out code in crew classes.
- Use `uv` only (not pip).
