## FR 03:
Implement the sandbox capability to let the agent write and run a Python file safely.

Here is the assignment: 
assignment = 'Write a python program to calculate the first 1,000,000 terms \
    of this series, multiplying the total by 4: 1 - 1/3 + 1/5 - 1/7 + ...'

    Create a file named assignment.md in the project directory. This file should be passed to the coder crew as the assignment.

implement main.py and crew.py to run this with the coder crew. The executer
should execute a Python file from the sandbox directory inside an ephemeral
Docker container, with the sandbox mounted as the working directory,
and return whatever the script printed to stdout.

Args:
    filename: The name of the Python file to run (e.g. "solution.py").
Returns:
    The text printed to stdout by the executed script.


You may want a tool list as the following:
sandbox_tools = [list_sandbox_files, read_sandbox_file, write_sandbox_file, run_sandbox_python]
1. list_sandbox_files — Lists files in the sandbox.
2. read_sandbox_file — Reads a file from the sandbox.
3. write_sandbox_file — Writes a file to the sandbox.
4. run_sandbox_python — Executes a Python file inside a Docker container.

Example subprocess within run_sandbox_python for docker execution:

    result = (subprocess.run(
        [
            "docker", "run", "--rm",
            "-v", f"{SANDBOX_DIR}:/workspace",
            "-w", "/workspace",
            "python:3.13-slim",
            "python", filename,
        ],
        capture_output=True,
        text=True,
        timeout=60,
    ))

    return result.stdout + "\n" + result.stderr

The coder agent must be configured to use the sandbox tools for listing, reading, writing, and executing Python files.

Python execution must be restricted to the sandbox directory and isolated from the host environment.

The execution tool must return useful error information when Python execution fails or times out.

The execution tool should also consider the subprocess return code.

Note: Try to keep the functional requirement in requirement.md and implementation details like file names, docker image names etc in plan.md.
